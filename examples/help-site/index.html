CADS-Tunnel

Dein Rechner bekommt eine echte, öffentliche Internetadresse — auch hinter NAT, Firewall oder im heimischen WLAN. Die Daten, die durchlaufen, kann nicht einmal der Betreiber dieses Tunnels lesen.

🔥 Was macht das eigentlich?

Du hast irgendwas auf deinem Rechner laufen — eine Web-App, einen Chat-Bot, einen kleinen Server, ein Spiel, egal — und willst, dass jemand anderes es im Browser aufrufen kann, ohne dass du einen eigenen Server mieten, Port-Forwarding im Router einrichten oder dich mit Zertifikaten rumschlagen musst.

Genau dafür ist der Tunnel da: ein kleines Programm (ct-agent) läuft auf deinem Rechner, baut eine Verbindung nach draußen auf und meldet „hol dir das, was hier lokal läuft, unter dieser Adresse ab". Die Nutzdaten sind dabei durchgehend verschlüsselt (Ende-zu-Ende, nicht nur bis zu uns) — wir als Betreiber der Vermittlungsinfrastruktur sehen nur, dass Daten fließen, nicht was drinsteht.

Kurz: dein Laptop wird für ein paar Minuten zu einem echten, im Internet erreichbaren Server — ohne dass du einer fremden Firma deine Daten unverschlüsselt anvertraust.

🚀 So geht's — in 3 Schritten

  1. Konto anlegen Im Portal mit deinem Google- oder GitHub-Konto anmelden. Kein Formular, kein Passwort, keine Kreditkarte — ein Klick, fertig.
  2. Tunnel erstellen Im Portal auf „Neuer Tunnel" klicken, einen Namen und den lokalen Port angeben, den du freigeben willst (z. B. 8080, falls dein Kram auf localhost:8080 läuft).
  3. Einen Befehl einfügen Das Portal zeigt dir danach einen fertigen Befehl für dein Betriebssystem (unten). Einfach ins Terminal / PowerShell einfügen, Enter drücken — der Befehl lädt den Agenten, meldet ihn bei uns an und startet den Tunnel. Kein manuelles Installieren, kein Neustart nötig.

Das war's. Sobald der Befehl durchgelaufen ist, ist deine Adresse live erreichbar — die URL steht direkt danach in deinem Terminal und in deinem Portal.

💻 Der Ein-Zeiler, nach System sortiert

Die folgenden Befehle bekommst du personalisiert im Portal nach Schritt 2 angezeigt (mit einem für dich einmalig gültigen, zeitlich begrenzten Token statt <dein-token>) — hier siehst du nur, wie sie aussehen und was sie tun.

🐧 Linux 🍎 macOS 🪟 Windows

Terminal öffnen, einfügen, Enter:

curl -fsSL https://bunsenbrenner.org/install.sh | CT_BOOTSTRAP=<dein-token> sh

Funktioniert auf jeder halbwegs aktuellen Distro (Ubuntu, Debian, Fedora, Arch, …) — curl reicht, sonst nichts.

Terminal öffnen (⌘+Leertaste → „Terminal"), einfügen, Enter:

curl -fsSL https://bunsenbrenner.org/install.sh | CT_BOOTSTRAP=<dein-token> sh

Derselbe Befehl wie unter Linux — macOS bringt curl von Haus aus mit.

PowerShell öffnen (Rechtsklick auf Start → „Windows PowerShell"), einfügen, Enter:

$env:CT_BOOTSTRAP='<dein-token>'; irm https://bunsenbrenner.org/install.ps1 | iex

Kein Admin-Rechte nötig, kein Installer-Fenster, keine Neustarts.

Sicherheits-Detail für alle, die's interessiert: das Token im Befehl ist nicht dein eigentliches Zugangs-Geheimnis — es ist selbst nur einmalig gültig und wird server-seitig gegen die echten Schlüssel eingetauscht. Selbst wenn dieser Befehl irgendwo in deiner Shell-History hängen bleibt, bringt er niemandem etwas, sobald er einmal benutzt wurde.

📶 Und danach?

Dein Tunnel läuft erstmal mit einem geteilten Zertifikat — das reicht für den Start völlig aus und funktioniert in jedem Browser ohne Warnung. Willst du später ein eigenes, auf deinen Namen ausgestelltes Zertifikat, steigst du im Portal mit einem Klick um:

Rot — noch nicht verifiziert Gelb — läuft, geteiltes Zertifikat Grün — eigenes Zertifikat, eigene Domain

Für die allermeisten reicht Gelb dauerhaft aus.

Quellcode, Architektur-Entscheidungen (ADRs), Bedrohungsmodell und Whitepaper: github.com/scimbe/CADS-Tunnel. Der Agent (ct-agent), den du eben installiert hast, hat sein eigenes Repo: github.com/scimbe/ct-agent — Quellcode einsehen, Binary selbst bauen, alles offen.

Ehrlich gesagt: Große Teile dieses Projekts — Code, Docs und auch diese Seite — sind mit Unterstützung eines LLM entstanden. Das Sicherheits-Design (Ende-zu-Ende-Verschlüsselung, provider-blinde Vermittlung) ist echt und im Whitepaper nachlesbar — Zahlen und Formulierungen drumherum bitte trotzdem kritisch prüfen. Und: das schützt die Vertraulichkeit deiner Daten, nicht deine Anonymität — Details im Bedrohungsmodell.
